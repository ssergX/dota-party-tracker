# dotabot — правила работы для Claude

Telegram-бот (aiogram 3, Python 3.12, SQLite, APScheduler) для пати Dota 2: лидерборд ранкед-игр,
карточки игроков, награды. Источник данных — OpenDota (+ Stratz как дополнение). Язык интерфейса и коммитов — русский.

## Как работать (главное)

1. **Сначала читай код, потом спрашивай.** Перед любым вопросом пользователю прочитай релевантные
   модули (`mmrbot/*.py`, схему в `storage.py`, `docs/design.md`, `README.md`, `tests/`). Вопрос
   допустим только если ответа нет в коде/доках и выбор реально меняет результат.
2. **Не задавай вопросы с очевидным ответом или с дефолтом.** Выбери разумный вариант, сделай,
   в конце одной строкой скажи, что выбрал. Не больше одного вопроса за раз, и только по делу.
3. **Не оспаривай то, что пользователь уже решил** (напр. выбранный вариант A «Stratz дополняет
   OpenDota»). Если пользователь говорит «это уже есть» — сначала перепроверь код (grep по
   схеме и хендлерам), а не переспрашивай.
4. Для новых фич — короткий дизайн (несколько абзацев) → одобрение → реализация через TDD.
   Не раздувай brainstorming: если фича понятна, дизайн должен занимать один ответ.

## Архитектура (маленькие модули, чистые функции отдельно от сети)

- `ids.py`, `ranks.py`, `stats.py`, `party.py`, `commands.py` — чистые, без сети, тестируются напрямую.
- `opendota.py` — синхронный `requests`-клиент (троттлинг, ретраи, lock), вызывается через `asyncio.to_thread`.
- `storage.py` — SQLite; схема в `_SCHEMA`, миграции делаются добавлением колонок.
- `tracker.py` — оркестровка: обновление игрока, сводки, награды. `formatting.py` — рендер (HTML).
- `bot.py` — тонкие хендлеры aiogram; разбор аргументов выносить в `commands.py`.
- Игрок = `(chat_id, account_id, display_name)`. **Привязки к Telegram user id в схеме нет**; игрок в команде
  указывается по нику (`display_name`), `@ник` резолвится так же (без `@`, без учёта регистра).
- Только ранкед (`lobby_type == 7`), отсчёт с `created_ts` игрока.

## Секреты

- Ключи (`BOT_TOKEN`, `OPENDOTA_API_KEY`, `STRATZ_API_KEY`) только в `.env` (в `.gitignore`).
  В `.env.example` — пустые заглушки. Никогда не коммить ключи, не печатать их в логах и ответах.
- Новая настройка → `config.py` + `.env.example` + строка в README.

## Тесты и проверка

- `pytest` (сейчас ~174 теста). Сеть в тестах не ходить: подставляй фейковую `session` / клиент.
- Баг-фикс или фича — сначала падающий тест. Перед «готово» запусти `pytest` и покажи результат.

## Git

- Коммиты в стиле существующих: `feat(scope): описание по-русски`, `fix(...)`, `perf(...)`, `chore(...)`.
- Коммить/пушить только по просьбе пользователя. Ветка по умолчанию — `main`.

## Окружение

- Windows 11, основной шелл PowerShell (Bash тоже есть). Команды префиксуй `rtk` (см. глобальный CLAUDE.md).
- Запуск: `python -m mmrbot`; Docker: `docker compose up -d --build`.
